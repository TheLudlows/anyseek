## 开销分布及改动

| 阶段 | 当前工作 | 处理方式 |
| --- | --- | --- |
| 捕获活动身份 | 扫描活动向量及元数据身份以判断是否纳入，编译过滤条件，将其与固定的原生身份关联，构建查询独有的集合、映射和比较用 ID | 移除单独的已接纳身份集合。地址映射只含**已接纳的身份**，同时用于成员判断和查找。另行保留选中的完整语料，使被过滤的记录仍计入语料统计。高选择性过滤不会增加查找条目数 |
| 语料选择 | 校验截断点、模式和修订唯一性，再扫描快照并构建每个视图的活动序号集合 | 已测量，本次保持原样。后续改动必须保持拒绝重复或缺失身份及固定读者的语义 |
| BM25 统计 | 遍历选定记录长度，读取查询词倒排表，按词跨字段去重文档频率 | 已测量，本次保持原样。没有增加每次提交时的全局文档频率维护，也没有改变算分规则 |
| 结果统计 | `Inner::statistics` 在 Inner 内统计当前记录数和物理版本数 | 复用现有保守的最早 TTL 到期时间界限。无 TTL 或界限严格晚于评估时间时，`locations.len()` 就是准确值。界限已到期或因过期状态而偏早时，沿用原来的可见性扫描。物理版本计数仍扫描序号槽 |
| 正文输出 | 对候选窗口评分 → 捕获身份和指纹 → 锁定 Inner → 校验当前身份和 TTL → 测量投影输出大小 → 复制选定字段 | 未发现评分前不必要的完整正文复制。测量和序列化与准入后最终复制分别是必要步骤，本 PR 沿用这两个步骤 |

沿用现有保守的查询内存准入。未引入缓存计数器、发布字段、持久化格式、共享尾部快照或每次查询的完整深拷贝。映射键仍归查询所有。锁释放、Searcher 与文件引用、退役传播、最终健康状态、版本、指纹及 TTL 检查、按 ID 稳定处理并列、字段排序、完整计数、分页、候选预算、跨组件评分及按全局排名进行的 RRF 均沿用原实现。

## 基线诊断分析

可选脚本 `instrument.py` 在**一次性检出目录**中加入本地阶段计时，无需启用运行时遥测或修改最终生产源码。第一次诊断采用 2,000 条 TTL 尚未到期的记录（release 构建、默认特性、Top-10、10 次预热及 60 个样本），所得阶段耗时中位数如下，单位毫秒。

| 模式 | 捕获（含获取锁） | 语料选择 | BM25 统计 | 评分与收集 | 重新校验与复制 | 返回统计 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 全文检索 | 1.656 | 1.172 | 0.309 | 0.798 | 0.024 | 0.192 |
| Count | 2.065 | 1.293 | 跳过 | 跳过 | <0.001 | 0.331 |
| 按 facet 排序 | 1.736 | 1.244 | 0.313 | 0.768 | 0.026 | 0.217 |
| Hybrid | 1.410 | 1.224 | 0.321 | 0.778 | 0.023 | 0.241 |

这些是含计时和日志开销的诊断墙钟耗时。端到端验收结果见后文。不能将各阶段中位数相加来计算查询百分位。捕获阶段计时包含等待，未单独测量锁等待。Hybrid 先执行的向量搜索不纳入这些全文检索阶段计时。

## 锁和 I/O 边界

Hybrid 仍先执行向量搜索。每个向量任务访问向量存储时持有组件读锁。随后全文检索阶段获取全部组件锁，捕获身份和固定原生快照，并在分析、统计、全文评分及融合期间继续持锁。按 facet 排序需要受锁保护的元数据 mmap，纯全文路径也会继续持锁。这些阶段可能推迟需要组件写锁的向量或元数据消费，以及尾部变更。Record 捕获和最终重新校验还使用 Inner 锁。持久化提交及之后的索引工作分开测量。

可脱离组件锁的纯全文路径仍在捕获后释放锁。捕获后共享尾部仍可能变化，因此仅复制 `VectorIndex` 或移动 `drop` 无法得到不可变读取视图。扩大脱锁范围需要单独评审身份、facet 和向量数据的所有权设计，并保留旧地址和退役语义。本 PR 不因此重构提交路径。下文的混合负载实测含全部写入和索引工作，无法将每一微秒单独归因于组件锁等待。

评分读取原生倒排表、长度及向量和元数据，正文留在 Record 状态中。仅对最终窗口从内存中的 Record 状态重新校验并投影。此路径无需为每个候选发送对象存储正文 GET，因而没有此类请求可合并。调整顺序或存储前，分别为远端冷缓存读取、精确向量重排、大正文和传输序列化设计工作负载。

## 复现与范围

`anyseek/examples/query_cost_probe.rs` 是手动运行的可执行程序，采用一次性本地目录和公开的 Record API。在独立工作树内，以同一构建参数构建基线和候选版本的同一探针源码。切换源码前复制各版本可执行文件：

```sh
CARGO_PROFILE_RELEASE_LTO=false cargo build --offline --locked --release \
  --example query_cost_probe -j 2
# Save target/release/examples/query_cost_probe as /tmp/query-before or query-after.
python3 benchmarks/query-cost/compare.py --before /tmp/query-before \
  --after /tmp/query-after --output /tmp/query-cost-pairs --cpus 6,7
python3 benchmarks/query-cost/compare.py --before /tmp/query-before \
  --after /tmp/query-after --output /tmp/query-cost-hybrid --cpus 6,7 \
  --workloads 2000:true --mixed hybrid
# Repeat the mixed command with --mixed lexical and --mixed facet, distinct outputs.
```

将本 PR 的探针复制到基线工作树，旧 master 暂无这一文件。使用新的输出目录。运行器拒绝覆盖运行目录，用 SHA-256 验证数据集副本，逐项比较结果 ID、顺序、分数位模式、通道排名及计数，并保留原始样本和可执行文件哈希。每项负载按 ABBA 顺序执行（每个版本两个进程），每种查询模式预热 10 次并测量 60 次。另行计时统计调用。请求时间排除构造和重新打开数据集，进程级 CPU 和墙钟耗时则包含重新打开及所有模式，因此不能作为单请求 CPU 耗时。

数据集采用两词元的短 ASCII 正文、小整数 facet、三维 F32 精确向量，结果窗口为 10 条，Hybrid 每通道 32 个候选。未来 TTL 固定为 4,000,000,000,000 ms。初始写入批大小为 32，校验全部回执并等待两个消费者。Busy 重试保留操作身份。混合负载使用一个持续读取者以及 30 次串行持久化更新，每次更新后等待两个消费者。发布样本包含提交、轮询（1 ms 间隔）和消费工作，无法作为细粒度锁计时。

尝试构造 8,000 条记录全部设 TTL 的数据集时，现有每条 TTL 预留 8,192 字节的到期处理预算和 16 MiB 帧上限使其在达到 2,048 条活动 TTL 记录后遭拒。性能数据排除了该尝试。有效工作负载为 1,000/2,000 条未来 TTL 记录，以及 8,000 条无 TTL 记录。基准未放宽预算。

## 最终成对结果

release 构建，默认 zh+vb，Rust 1.99.1，`opt-level=3`，`LTO=false`，使用原生 CPU 标志。Linux 容器的配额为 8 个 CPU，内存限制 8 GiB，采用本地 overlay 文件系统（物理底层未确认）。每个测量进程使用 CPU 6,7 和两个 Tokio worker，数据集及进程所有权各自独立。最终序列在**本任务的构建和正确性测试结束后**启动。宿主机共享，未独占物理 CPU。与测试重叠的初步运行用于探索，未纳入以下验收表。

### 持续读写

2k 未来 TTL，一个持续读取者，每进程 30 次更新。每个版本两个进程，写入列按每版本 60 次更新汇总。读取持续到写入和索引结束，查询样本量因而可变。全部 12 个混合负载进程都在每次写入后完成两个消费者的工作，查询 Busy 和写入重试均为零。上述结果验证短期进展，长期饥饿和关闭行为另需测试。

| 读取模式 | 提交 P50 A → B | 提交及两个消费者 P50 A → B | 发布 P95 A → B | 查询 P50 A → B |
| --- | ---: | ---: | ---: | ---: |
| 全文检索 | 1.238 → 1.209 | 22.954 → 25.484 | 47.785 → 46.628 | 5.035 → 4.171 |
| facet | 1.330 → 1.083 | 30.026 → 23.887 | 51.989 → 42.412 | 5.285 → 4.074 |
| Hybrid | 1.076 → 1.000 | 25.812 → 27.091 | 41.616 → 45.260 | 5.234 → 4.245 |

发布中位数在**全文检索下回退 11.0%**，在 **Hybrid 下回退 5.0%**，Hybrid 发布 P95 上升 **8.8%**。此次 facet 有改善，早期探索数据存在波动。读端加速后，在同一写入序列内执行的查询也增加了（全文 281→358，facet 341→360，Hybrid 292→363），因此不能按固定 QPS 的隔离写入实验解读。证据支持查询自身工作减少，尚不足以得出写入吞吐或锁等待普遍改善的结论。Hybrid 和 facet 的组件锁持有范围仍是独立瓶颈。

## 正确性验证与检视

- 在 Linux 默认特性下，现有清单内的 **194 个精确指定的内核用例**均通过。覆盖更新和删除时的协调、同版本向量补写、TTL 截止点、提前、延长、删除及恢复 TTL 界限、尾部轮换、原生合并、旧读者退役和文件引用，以及取消和失败防护。
- 在现有的最终 TTL 重新校验用例中补充未来 TTL 计数和查询断言，沿用现有测试名和 CI 矩阵。已有界限测试覆盖过时且偏早的界限，并在校验时拒绝过晚或缺失的界限。
- `stable_ranking`、`weighted_rrf`、`server_shared_filters`、`lexical_correctness`、`bitmap_delete_consistency`、`union_count_cross_block`、`frequent_topk_consistency`、`union_topk_fill_ranking` 和 `union_topk_many_terms` 中的 **21 个现有集成测试**通过（小规模）。验证字段排序、过滤、两种字段长度策略、完整评分基准、分页及全局 RRF 排名。
- 生产 release 探针以 `cfg(test)=false` 构建。最终 24 个对比进程的固定数据集签名全部精确一致。最终未加计时的库测试二进制经检查仍为当前版本，无需重新编译。静态源码分区、控制台边界、Python 语法及 diff 空白检查均通过。
- 源码检视确认语料身份未经过滤，映射仅为已接纳命中项查找，失败或重复的原生选择仍报错，查询所有的字符串在读取期间持续有效，现有 TTL 界限仍保持保守，固定引用、退役、最终重新校验和锁范围保持原有语义。检视由实现改动的代理执行，未开展独立检视。

未执行本地 Windows、全量手动验收、真实 HTTP 或 S3 性能、高选择性过滤性能、大正文及向量负载、冷缓存、分配峰值和长期容量或饥饿测试。PR CI 按实际提交单独记录，无法替代这些实测。最初全 TTL 容量拒绝和基准 Busy 处理在手动探针中修正，未通过放宽引擎准入掩盖。

后续工作包括减少语料选择和身份的重复扫描并精确保留截断点、重复和缺失检查，分别测量长度、文档频率和物理序号扫描，先设计安全的 Hybrid 与 facet 脱锁所有权再移动锁，以及实测固定 QPS 下的混合流量和大载荷 I/O。范围不含共享尾部、提交协议和向量算法重构。
