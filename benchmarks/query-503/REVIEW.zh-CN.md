# 独立审查与请求期限跟进

**简体中文** · [English](REVIEW.md)

独立审查者（`/root/independent_review`）检查了 `bba809f`，未改动实现或运行性能负载。核对失败封锁和修订校验、发布失败、取消、慢客户端、旧响应、生命周期所有权、锁顺序和饥饿。独立复跑既有持久化失败和慢客户端服务测试，两项通过。

## 发现和修复

**P1：响应头与正文发布等待未受原请求期限限制。** 响应头中间件在 `request_guard` 外，其新增 await 因此在 `timeout_at` 外。正文可能等待、被下一轮发布抢先、再次等待而无总时限。FIFO mutex 公平性无法保证连续写入时响应帧得到交付机会。问题由代码审查发现。此前两轮短矩阵均无超时，不能据此证明等待有界。

修复将头部发布门控移入原请求预算。查询响应构造时捕获相同的绝对期限，所有正文等待和整个重试循环沿用它。到期丢弃未发送字节并产生 `io::ErrorKind::TimedOut`。超时发生于响应头之前时，用原 HTTP 503 `outcome_unknown` 响应。头部发出后只能产生正文传输错误，不能改 HTTP 状态。任何超时均不取消已接管的持久写入。

独立审查者复核差异后确认 P1 已覆盖，没有其他已确认阻塞缺陷。另发现测试误以为只有一层 `axum::Error`。测试现沿来源链查找底层 I/O 错误。

新确定性服务测试使用 50ms 请求预算及暂停的索引发布，覆盖已完成 handler 等待响应头交付、已创建正文等待发布，以及正文在原期限后首次被轮询三种情况。检查超时分类、有无数据交付、写入继续完成及正常关闭。晚轮询必须立即失败，避免首次轮询时生成新预算。

该改动限制发布等待，**不覆盖整个网络传输生命周期**。普通未消费响应仍持有字节、额度与关闭活动，直到消费或丢弃。正文尚未轮询时等待任务可以独立结束，不会持发布 mutex 等客户端。

## 验证

修复后用 release 与显式故障注入 feature 运行，**33 个服务测试全部通过**，覆盖三个期限用例、真实持久化/索引故障、取消、慢客户端、代次和关闭。27 个未变化的引擎回归已通过。独立审查者核对最终差异与 33 项测试日志，未发现阻塞问题。`git diff --check` 通过。本历史审查未开 PR 或推送分支。
