Connect & create an index

Paste the Master API key printed in the server console or Docker logs to connect and create indexes.

Saved only in this browser tab's session. Use “Forget key” on a shared computer.

Service backup and recovery (master key)

Create a consistent local snapshot of the catalog, retained collections and collection backups. Recovery creates a new stopped service root. Historical keys stay disabled; only the current master can access restored data.

Take over a collection (master key)

Permanently close the original collection and recover all writes through its final sealed state into a new collection. The backup must belong to the live original. Old grants are not copied. Missing current history cannot be bypassed.

Create index

Must match your external embedding model. Vectors are supplied in the “vector” document field; this server does not generate embeddings.

Default fields: title, body and url. Vector/Hybrid also include vector (F32, cosine similarity).

Advanced: field schema (JSON)

Edit field names, storage, lexical/vector indexing and filter/sort metadata. Changing search mode resets this schema.

Creates an empty index. Then choose “Write data” to add JSON records.

Write JSON data

Index:

Paste one JSON object or an array of objects. Records are added as new documents. Field names and types must match the index schema; vectors are supplied externally and may be added after the body. Records without vectors do not participate in vector recall.

Index fields







Envelope fields: record_id, routing_key, expected, document and optional system. Source: system.kind="source". Derived: system.kind="derived" with evidence_refs [{record_id,routing_key,version}]. References stay in this collection. Source updates require expected Match of the current version; old dependent content becomes stale and hidden. Recompute derived content under a new ID using current evidence. Deleted identities cannot be recreated. Set document to null to delete; dependent content is immediately hidden. To fill missing vector fields, use vector_patch with expected Match of the body version and omit document/system. This preserves the body version. For a document generation, omit document/system and set generation.action to stage with generation_id, source, complete members and chunks. Stage is durable but not searchable. Publish it with generation.action="publish", the same generation_id and expected Match of the control version (first stage: 1). Optional temporal metadata uses UTC milliseconds: event_time_ms, valid_from_ms (inclusive), valid_to_ms (exclusive), expire_at_ms. TTL expiration is irreversible and hides dependents; extending an expired TTL cannot restore an identity. Business-valid dates do not imply TTL. Generation chunks may also include temporal. Operation IDs are generated and retained for retries.













Change feed and snapshot bootstrap

Notices contain identities, never historical bodies. Bootstrap pages share a fixed cut and return a feed continuation. A rescan notice or expired cursor requires a new bootstrap; do not combine pages from different cuts. One bounded five-minute snapshot is allowed per collection.









Entities and explicit one-hop relations

Declare an entity using system.kind="entity". For an edge use system.kind="relation" and system.relation={from:{record_id,routing_key,version},to:{record_id,routing_key,version},relation_type,weight}. Both exact endpoints must be visible in this collection. Evidence is declared separately in evidence_refs. Changing an endpoint version hides old edges; rebind using a new edge identity. No automatic entity merging or graph traversal.
