## 容量与架构边界

完整逻辑 State 仍驻内存，有限准入和显式缓冲预算不是全进程 RSS 或全磁盘硬上限。默认服务共用 SQLite authority 和其旁的校验对象缓存；多 authority 的库使用场景、物化索引和独立备份仍需整体容量评估。不得根据旧的“每集合独立 authority”布局推算当前默认服务缓存总量。

SQLite 仅保存协调元数据，规范原文/原向量归 Payload，Tantivy 与向量/元数据组件保存派生检索数据。幂等历史回收保留期限、恢复对象闭包/备份保护和持久 epoch 拒绝规则，不通过删除窗口内回执解除容量限制。

超大 collection 分片、自动 split/merge、跨主机 HA、直接远端 Directory、预取与自动调度按实际容量需求后置。保留必要提交、索引有效性与恢复校验；不预设统一内部水位、UUID 替换 Operation ID 或重建执行框架。来源、关系和记忆策略已上移应用层；模型推理、解析切块、Embedding/Reflect、SQL/JOIN、完整图语言和旧格式迁移不进入本轮。
