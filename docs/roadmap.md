# 后续路线与验收证据

核对基线：2026-11-07 主干 `3e0a9a4`（#203）。本文集中维护剩余工作和证据入口；当前能力见[功能与边界](features.md)，实现见[架构](architecture.md)，接口与资源限制见[服务指南](../anyseek/src/server/README.md)。合入不等于发布或完成性能验收。

| 1 | 写入成本与轻量可见发布 | 普通写已使用成功前缀增量规划，多条同步写共享持久提交；#203 新增 WAL 支撑的可查全文增量、后台原生物化，以及 WAL 前全文/组件工作区预留。继续测真实持久盘、单条写、切段、维护与背压成本，旧测量不能直接描述当前写入路径 |
| 2 | 同步可见与异步追平验收 | `/batch` 保持 durable + visible，可查全文增量不必等待原生文件物化；`/ingest` 仍只保证持久业务结果。验证真实混合负载、固定旧读者、更新删除、补向量与过滤；原生 fallback、checkpoint 和切段仍可能等待 I/O，不能宣称所有写入已无阻塞 |
| 3 | 查询辅助成本与锁范围 | 已有有界候选、部分纯全文路径释放组件锁及身份映射/计数优化；#203 将原生 I/O mutex 缩至同一物理目录。继续测语料统计、physical_versions、多集合进展及 Hybrid/字段排序锁范围，不以目录微基准代替服务吞吐或 P99 验收 |

| 6 | 发布验收 | 固定候选 SHA 跑 Linux/Windows 完整矩阵；真实 S3、系统/文件系统崩溃、断电及跨 AES 分别记录执行结果，快速 CI 不能替代 |

## 容量与架构边界

完整逻辑 State 仍驻内存；10 万档是准入上界，不是任意数据形态的容量承诺。有限准入和显式缓冲预算不是全进程 RSS 或全磁盘硬上限。默认服务共用 SQLite authority 及其校验对象缓存；多 authority、物化索引和独立备份仍需整体评估。

回执默认最早两日后具备回收资格，另受重试窗口、认证 history floor、epoch、读者与备份保护约束，不是固定清理期限。不能通过删除窗口内回执解除容量限制。S3 模式必须保留 metadata.sqlite、SQLite WAL 与 owner 锁文件，不能只凭 bucket 重建权威；SQLite 首版不提供跨主机 HA 或权威卷丢失零 RPO。

超大 collection 分片、自动 split/merge、跨主机 HA、直接远端 Directory、预取与自动调度按实际容量需求后置。#107 的 Catalog/Generation 研究 PR #110 已关闭，只有实际负载证明确有瓶颈时再启动测量。不预设统一内部水位、UUID 替换 Operation ID 或重建执行框架。来源、关系和记忆策略在应用层；模型推理、解析切块、Embedding/Reflect、SQL/JOIN、完整图语言和旧格式迁移不进入本轮。
