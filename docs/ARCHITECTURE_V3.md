## §1 概述与定位

### 1.1 产品定位

SeekPower v3 是一个**对象存储原生的多租户混合搜索引擎**，专为生产环境大规模部署设计。

**核心能力**：
- 🏢 **多租户隔离**：目录级物理隔离，支持无限租户
- 🔍 **混合检索**：聚类向量搜索 + 自研倒排全文检索 + RRF 融合
- 🚀 **实时索引**：写入后毫秒级可查，无需预创建 schema
- 💾 **成本优化**：基于磁盘存储，支持数十亿向量
- 🔒 **高可用**：对象存储原生，天然支持多副本和灾难恢复

### 1.2 与 v2 的核心差异

| 维度 | v2 设计 | v3 设计 |
|------|---------|---------|
| 向量索引 | RaBitQ（1-bit 量化） | 聚类索引（SPFresh 风格） |
| 多租户 | 无明确设计 | 目录级物理隔离 |
| Schema | 预定义 Schema | Schema-Free，自动推断 |
| 实时性 | 提交后可查 | 写入后立即可查 |
| 存储策略 | 内存+磁盘混合 | 磁盘优先，内存缓存 |
| 目标场景 | 嵌入式引擎 | 生产级多租户服务 |

## §2 核心设计决策

### 2.1 设计原则

| 原则 | 说明 |
|------|------|
| **对象存储优先** | 所有数据持久化到对象存储，引擎无状态 |
| **目录级隔离** | 每个租户独立前缀，天然多租户 |
| **实时索引** | 写入 WAL 后立即可查，提交异步化 |
| **Schema-Free** | 自动推断字段类型，无需预定义 |
| **成本敏感** | 磁盘存储，按需加载，低内存占用 |
| **一致性保证** | WAL + 版本化 manifest，ACID 语义 |

### 2.2 技术选型

| 组件 | 技术方案 | 理由 |
|------|----------|------|
| 向量索引 | 聚类索引 | 高精度召回，磁盘原生，内存可控 |
| 全文检索 | 自研倒排索引 | 与对象存储深度集成，BM25F 支持 |
| 分词器 | Tantivy Tokenizer | 成熟方案，多语言支持 |
| 存储后端 | 对象存储 Trait | 支持 S3/FS/内存，云原生 |
| 实时索引 | WAL + 内存索引 | 写入立即可查，提交异步持久化 |
| 多租户 | 目录隔离 | 物理隔离，策略简单，天然支持 |
| 距离度量 | 余弦 / 欧氏 / 点积 | 三种都支持，灵活配置 |
| 向量维度 | 固定维度 | 简化存储和查询逻辑 |

## §4 多租户隔离设计

### 4.1 隔离策略：目录级物理隔离

每个租户拥有独立的对象存储前缀，实现物理隔离：

```
object-store://bucket/
├── tenant-{tenant_id}/
│   ├── registry.json          # 租户元数据
│   ├── indexes/
│   │   ├── index-{name}/
│   │   │   ├── manifest.json  # 索引 manifest
│   │   │   ├── wal/           # WAL 文件
│   │   │   ├── segments/      # 段文件
│   │   │   │   ├── seg_{id}/
│   │   │   │   │   ├── clusters.meta # 聚类元数据
│   │   │   │   │   ├── vectors.bin  # 向量数据
│   │   │   │   │   ├── lex.bin      # 倒排索引
│   │   │   │   │   └── field.json   # 字段统计
│   │   │   └── docs/          # 文档原文
│   │   │       └── doc_{doc_id}.json
│   │   └── ...
│   └── quota/                 # 配额信息
└── tenant-{tenant_id}/
    └── ...
```

### 4.2 租户元数据

**TenantRegistry** 结构包含：
- 租户 ID、名称、状态、创建时间
- 配额限制（最大索引数、最大文档数、最大存储容量、QPS 限制）
- 索引列表

### 4.3 租户路由

**TenantRouter** 提供以下功能：
- 从对象存储加载租户元数据，支持缓存
- 构建租户级对象存储路径：`tenant-{tenant_id}`
- 构建索引路径：`tenant-{tenant_id}/indexes/{index_name}`

### 4.4 资源配额

租户级别的资源配额由 `QuotaManager` 在每次操作时检查：

| 操作 | 检查点 |
|------|--------|
| 创建索引 | `max_indexes` |
| 索引文档 | `max_documents`, `max_storage_bytes` |
| 搜索查询 | QPS 限制（令牌桶） |

## §6 Schema-Free 设计

### 6.1 自动 Schema 推断

无需预定义 schema，引擎自动推断字段类型：

**FieldType 类型**：
- Text：文本，分词索引
- Keyword：关键词，精确匹配
- U64/I64/F64：数值类型
- Bool：布尔值
- Timestamp：时间戳
- Vector(u32)：向量（固定维度，自动推断）
- Json：JSON 对象（不索引）

**FieldMetadata** 包含字段名称、类型、是否索引、是否存储、首次出现时间、样本数量

### 6.2 Schema 推断策略

| 字段值 | 推断类型 | 策略 |
|--------|----------|------|
| String < 100 字符 | Keyword | 短文本精确匹配 |
| String ≥ 100 字符 | Text | 长文本分词索引 |
| Float 数组 | Vector(dim=长度) | 向量索引（固定维度） |
| Integer | I64 | 数值索引 |
| Boolean | Bool | 布尔索引 |
| Object | Json | 不索引，仅存储 |

**类型收敛规则**：当字段类型冲突时，升级为更通用类型：
- Keyword + Text → Text
- I64 + F64 → F64
- 其他冲突 → Json

**向量维度约束**：首次推断后维度固定，后续写入不一致维度报错。

### 6.3 Schema 存储与演化

Schema 随 manifest 持久化，包含版本、字段映射、创建/更新时间。

**推断逻辑**：
- 对文档中每个字段，检查是否已存在
- 如果存在，更新样本计数，检查类型收敛
- 如果不存在，推断类型并创建新字段
- 更新修改时间

## §7 聚类向量索引

### 7.1 SPFresh 风格聚类基础结构

基于 K-Means 聚类的向量索引，受 SPFresh 启发：

```
                    ┌─────────────────┐
                    │  Query Vector q │
                    └────────┬────────┘
                             │
                    计算到各聚类中心的距离
                             │
           ┌─────────────────┼─────────────────┐
           ↓                 ↓                 ↓
    ┌──────────┐      ┌──────────┐      ┌──────────┐
    │ Cluster  │      │ Cluster  │      │ Cluster  │
    │   Top-K  │      │  Others  │      │  Others  │
    └────┬─────┘      └────┬─────┘      └────┬─────┘
         │                 │                 │
    在选定的聚类中搜索        │                 │
         │                 │                 │
         └─────────────────┴─────────────────┘
                             │
                        合并结果
                             │
                        Top-K
```

### 7.2 磁盘布局设计

#### 聚类元数据存储

```

│ Header:                                      │
│   - format_version: u32                      │

│   - dimension: u32                           │
│   - distance_metric: DistanceMetric          │
│   - max_vectors_per_cluster: u64             │
├─────────────────────────────────────────────┤
│ Cluster Centers:                             │
│   For each cluster:                          │
│     - cluster_id: u32                        │
│     - center: [f32; dimension]               │
│     - num_vectors: u64                       │

├─────────────────────────────────────────────┤
│ Cluster Statistics:                          │
│   For each cluster:                          │
│     - avg_radius: f32                        │
│     - max_radius: f32                        │

#### 向量数据存储（按聚类分区）

┌─────────────────────────────────────────────┐

│   - format_version: u32                      │
│   - dimension: u32                           │

│ Cluster 1 Vectors...                         │
├─────────────────────────────────────────────┤

└─────────────────────────────────────────────┘
```

#### 文档 ID 映射

```
segments/seg_{id}/doc_ids.bin
┌─────────────────────────────────────────────┐
│ Header:                                      │
│   - format_version: u32                      │
│   - num_vectors: u64                         │
├─────────────────────────────────────────────┤
│ Doc ID Mapping (cluster_id, local_id → doc_id): │
│   For each cluster:                          │
│     - cluster_id: u32                        │

│     - doc_ids: [u64; num_vectors]            │

```

### 7.3 距离度量

支持三种距离度量：
- **Cosine**：1 - 余弦相似度（归一化后使用）
- **Euclidean**：L2 距离平方
- **Dot**：1 - 点积（适用于归一化向量的相似度搜索）

### 7.4 查询流程

```
搜索 Query Vector q
       ↓
1. 计算到所有聚类中心的距离
       ↓
2. 选择距离最近的 nprobe 个聚类
       ↓
3. 并行搜索选定的聚类
       ↓
4. 计算精确距离（从 vectors.bin 读取）
       ↓
5. 合并并排序结果
       ↓
6. 返回 Top-K
```

**ClusterIndex** 包含：
- 对象存储引用、聚类元数据、维度、距离度量
- nprobe 参数：搜索时选择的聚类数量

**search** 方法逻辑：
1. 计算到所有聚类中心的距离
2. 选择最近的 nprobe 个聚类
3. 并行搜索选定的聚类
4. 合并结果并排序
5. 返回 Top-K

**search_cluster** 方法逻辑：
- 从磁盘加载指定聚类的向量和文档 ID
- 计算查询向量与所有向量的距离
- 返回排序后的 Top-N 结果

### 7.5 聚类缓存策略

- **聚类中心缓存**：所有聚类中心常驻内存
- **热度统计**：跟踪每个聚类的访问频率
- **按需加载**：向量数据按需加载（LRU）
- **预取**：搜索时预取邻近聚类

**ClusterCache** 包含：
- 聚类中心（常驻内存）
- 热聚类向量缓存（LRU）
- 访问频率统计

### 7.6 聚类构建

**ClusterBuilder** 使用 Mini-Batch K-Means 算法：
1. 初始化聚类中心
2. 迭代：将向量分配到最近的聚类，更新聚类中心
3. 返回聚类元数据（数量、维度、中心点、距离度量）

## §8 自研倒排索引

### 8.1 段内结构

```
segments/seg_{id}/lex.bin
┌─────────────────────────────────────────────┐
│ Header:                                      │
│   - format_version: u32                      │
│   - num_fields: u32                          │
│   - doc_count: u64                           │
├─────────────────────────────────────────────┤
│ Field Metadata Table:                        │
│   For each field:                            │
│     - field_name_len: u16                    │
│     - field_name: [u8]                       │
│     - fst_offset: u64                        │
│     - postings_offset: u64                   │
│     - field_statistics_offset: u64           │
├─────────────────────────────────────────────┤
│ Field Statistics (per field):                │
│   - sum_total_tf: u64                        │
│   - sum_doc_len: u64                         │
│   - doc_count: u64                           │
│   - avg_doc_len: f64                         │
├─────────────────────────────────────────────┤
│ Term Dictionary (FST):                       │
│   term → (postings_offset, term_freq, df)   │
├─────────────────────────────────────────────┤
│ Postings Lists:                              │
│   For each term:                             │
│     - doc_count: u32                         │
│     - doc_id_list: [delta varint]           │
│     - term_freq_list: [varint]              │
│     - positions_list (optional):             │
│       For each doc:                          │
│         - num_positions: u16                 │
│         - positions: [delta varint]         │
└─────────────────────────────────────────────┘
```

### 8.2 分词器集成

复用 Tantivy Tokenizer：

**Tokenizer Trait**：提供 tokenize 方法
**JiebaTokenizer**：封装 Tantivy 的中文分词器，返回 Token 列表

### 8.3 BM25F 评分

**Bm25fScorer** 包含参数 k1、b 和字段权重映射。

**score 计算**：
1. 获取字段权重
2. 计算 IDF：ln((total_docs - df + 0.5) / (df + 0.5) + 1.0)
3. 计算 TF 归一化：tf * (k1 + 1) / (tf + k1 * (1 - b + b * doc_len / avg_doc_len))
4. 返回 field_weight * idf * tf_norm

### 8.4 查询执行

**LexicalIndex** 包含对象存储引用、段列表、删除集。

**search 方法**：根据查询类型分发到对应的搜索方法
- Term 查询：单个词项搜索
- Phrase 查询：短语搜索（支持 slop）
- Boolean 查询：布尔组合（must/should/must_not）

**term_search 方法**：
1. 并行搜索所有段
2. 合并结果并过滤删除集
3. 返回 Top-K

## §10 实时索引机制

### 10.1 写入流程

```
1. API 接收文档
2. 写入 WAL（同步）
3. 更新内存索引（同步）
4. 返回成功（立即可查）
5. 后台 Commiter：
   - 检查 WAL 大小 / 时间
   - 构建 SST 段
   - 更新 Manifest
   - 清理 WAL
```

### 10.2 WAL 格式

```
wal/{seq}.wal
┌─────────────────────────────────────────────┐
│ Header:                                      │
│   - magic: [u8; 4] = b"WLOG"                │
│   - version: u32                             │
│   - checksum: u32                            │
├─────────────────────────────────────────────┤
│ Records:                                     │
│   For each record:                           │
│     - record_type: u8 (ADD/DELETE)          │
│     - doc_id: u64                            │
│     - payload_len: u32                       │
│     - payload: [u8]                          │
│     - checksum: u32                          │
└─────────────────────────────────────────────┘
```

### 10.3 内存索引结构

**MemoryIndex** 包含：
- 向量内存索引：(doc_id, vector)
- 倒排内存缓冲：(field, term) → [(doc_id, freq)]
- 文档缓冲：doc_id → Document
- 下一个 doc_id（原子计数器）

**insert 方法**：
1. 分配 doc_id
2. 存储文档
3. 提取向量并添加到向量索引
4. 分词并构建倒排索引
5. 返回 doc_id

### 10.4 内存 + 磁盘查询

查询时合并内存和磁盘索引：
1. 并行查询内存和磁盘索引
2. 合并结果，去重（取最大分数）
3. 排序并返回 Top-K

## §11 混合搜索与融合

### 11.1 RRF (Reciprocal Rank Fusion)

**RrfFusion** 包含词法权重、向量权重、RRF 常数 k（通常 60）

**fuse 方法**：
1. 累加词法搜索 RRF 分数：weight / (k + rank)
2. 累加向量搜索 RRF 分数：weight / (k + rank)
3. 按 RRF 总分排序并返回

### 11.2 元数据过滤

支持在融合前进行元数据过滤：
1. 先应用过滤条件获取 doc_id 集合
2. 在过滤后的集合上执行词法和向量搜索
3. 融合结果

## §13 并发模型

### 13.1 锁策略

```
Index:
  ├── manifest: RwLock<IndexManifest>
  ├── schema: RwLock<Schema>
  ├── segments: Arc<Vec<SegmentMeta>>  (不可变，替换时 CAS)
  ├── memory_index: Arc<MemoryIndex>
  │   ├── vectors: RwLock<...>
  │   ├── postings: RwLock<...>
  │   └── documents: RwLock<...>
  ├── delete_set: Arc<RwLock<RoaringBitmap>>
  └── next_doc_id: AtomicU64
```

### 13.2 写入并发

**index_document 流程**：
1. 获取 doc_id（原子操作）
2. 写入 WAL（单线程）
3. 更新内存索引（细粒度锁）
4. 检查是否触发 commit，如果需要则异步提交

### 13.3 查询并发

**search 流程**：
1. 获取 manifest 和 schema 读锁（快照）
2. 释放锁，并行执行词法和向量搜索
3. 融合结果
4. 过滤删除集

## §14 缓存策略

### 14.1 多级缓存

```
                  ┌──────────────┐
                  │   L1 Cache   │  ← 进程内 LRU
                  │  (Hot Data)  │
                  └──────┬───────┘
                         │ miss
                  ┌──────▼───────┐
                  │   L2 Cache   │  ← 对象存储缓存
                  │  (Warm Data) │
                  └──────┬───────┘
                         │ miss
                  ┌──────▼───────┐
                  │   Object     │
                  │   Storage    │
                  └──────────────┘
```

### 14.2 缓存策略

| 数据类型 | 缓存层级 | 策略 |
|----------|----------|------|
| Manifest | L1 | 短缓存（1s），版本验证 |
| Schema | L1 | 长缓存（10min） |
| 聚类中心 | L1 | 常驻内存 |
| 聚类向量数据 | L1+L2 | LRU，预取 |
| 文档 ID 映射 | L1+L2 | LRU，按需 |
| Vectors | L2 | Range read，LRU |
| FST Dictionary | L1 | 常驻内存（小） |
| Postings Lists | L1+L2 | LRU，按需 |
| Documents | L2 | LRU，按需 |

### 14.3 缓存实现

**CacheManager** 包含：
- L1：进程内 LRU 缓存
- L2：对象存储缓存
- 统计信息

**get 流程**：
1. 查找 L1，命中则返回
2. L2 查找
3. 回填 L1
4. 更新统计

## §15 创新设计亮点

### 15.1 目录级多租户物理隔离

**创新点**：
- 每个租户独立的对象存储前缀，天然隔离
- 租户级别独立的资源配额管理
- 支持按租户迁移和备份

**优势**：
- 实现简单，无需复杂的权限逻辑
- 支持按租户扩展到不同的存储后端
- 天然支持多区域部署

### 15.2 Schema-Free 自动推断

**创新点**：
- 无需预定义 schema，自动推断字段类型
- 类型自动收敛，兼容性优先
- Schema 演化无锁，向后兼容

**优势**：
- 开发体验佳，快速迭代
- 适应动态数据结构
- 降低使用门槛

### 15.3 聚类向量索引 + 实时索引

**创新点**：
- 受 SPFresh 启发的 K-Means 聚类索引，磁盘原生
- 聚类中心常驻内存，向量数据按需加载
- 查询时只在最近的 nprobe 个聚类中搜索，大幅减少 I/O
- WAL + 内存索引实现实时可查

**优势**：
- 高精度召回（P99 < 100ms）
- 支持十亿级向量规模
- 内存占用可控（仅缓存聚类中心和热聚类）
- 写入延迟 < 10ms

### 15.4 原文分离 + 按需加载

**创新点**：
- 索引和原文完全分离
- 搜索结果只返回 doc_id
- 原文异步按需加载

**优势**：
- 索引查询延迟极低
- 支持大规模文档存储
- 灵活的存储策略

### 15.5 多距离度量支持

**创新点**：
- 支持余弦、欧氏、点积三种距离度量
- 灵活配置，适应不同场景
- 固定维度简化存储和查询

**优势**：
- 一套索引支持多种搜索场景
- 无需重建索引即可切换距离度量
- 更广泛的适用性

### 15.6 复用 Tantivy 分词器

**创新点**：
- 复用成熟的 Tantivy 分词器
- 支持多语言分词
- 降低开发成本和风险

**优势**：
- 成熟稳定，经过大量验证
- 支持中文、英文等多语言
- 丰富的分词器生态

## §18 可靠性保证

### 18.1 ACID 语义

- **原子性**：WAL + 两阶段提交
- **一致性**：Manifest 版本化 + Schema 约束
- **隔离性**：RwLock + MVCC（读快照）
- **持久性**：WAL 同步写入 + 对象存储持久化

### 18.2 灾难恢复

1. **WAL 恢复**：启动时重放 WAL，重建内存索引
2. **Manifest 恢复**：从对象存储加载最新 manifest
3. **段恢复**：加载所有活跃段
4. **删除集恢复**：从 manifest 加载删除集

### 18.3 数据一致性

- **CAS 写入**：Manifest 更新使用 If-Match
- **校验和**：所有文件带 CRC32 校验
- **版本验证**：读取时验证 manifest 版本

## 设计决策总结

| 决策项 | 选择的方案 | 理由 |
|--------|-----------|------|
| 多租户隔离 | 目录级物理隔离 | 简单、安全、可扩展 |
| 全文检索 | 自研倒排索引 | 与对象存储深度集成 |
| 向量索引 | 聚类索引（SPFresh 风格） | 高精度、低内存、可扩展 |
| 文档存储 | 原文独立存储 | 查询快、存储灵活 |
| Schema | Schema-Free | 降低使用门槛 |
| 实时性 | WAL + 内存索引 | 写入后立即可查 |
| 向量维度 | 固定维度 | 简化存储和查询 |
| 距离度量 | 余弦/欧氏/点积 | 三种都支持，灵活 |
| 分词器 | 复用 Tantivy | 成熟、稳定、多语言 |
| 压缩 | 暂不考虑 | 简化实现 |
| 冷热分离 | 不需要 | 简化架构 |
| 跨租户搜索 | 不需要 | 专注单租户 |
