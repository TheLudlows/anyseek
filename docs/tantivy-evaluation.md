# Tantivy 全文引擎设计

原评估基于 master `3893cd54`；#80 已实施，当前完成度见 [STATUS](../STATUS.md)。本文仅保留选型边界和取舍，历史评估与阶段过程可从 Git 历史查阅。

## 已采用的边界

| 层 | 责任 |
| --- | --- |
| Record | 稳定身份/版本/幂等、来源隐藏、TTL、generation、关系和授权；业务提交与可见性权威 |
| Payload | 唯一保存规范原始 Document 和原始向量；量化向量不能代替输入 |
| Tantivy 0.27.0 | 全文倒排、词典、位置与固定 Searcher；不另存完整正文，不决定业务 head |
| 向量/元数据 | 独立组件；与全文固定同一业务 cut 和 evaluation_time |
| 本地证书 / SQLite | 认证选择不可变包与完整 tail；SQLite 仅保存必要协调元数据 |
| S3 | 不可变对象与认证文件闭包；本地完整物化后检索，不增加远端同步随机读 Directory |

Tantivy 不能读取旧倒排字节；Directory 只改变文件访问方式，不能转换格式。采用新格式并删除旧全文执行器和低层公开 API，不建设多引擎框架、迁移器、旧格式读取或双写。新格式内的恢复、备份、GC 和既定数据正确性契约继续保留；该决定不授权删除已有部署数据。

## 保留的语义与实现取舍

- 写入成功仍为 durable + visible。原生 commit/reload 形成候选 Searcher，只有业务权威认证后才能选择；不得以异步刷新代替即时可见。
- 查询固定 Searcher；可见性、字段/元数据过滤在 Top-K 前执行。DocAddress 只在快照内部有效，持久身份通过认证 Record/版本映射确定。
- 保留实际启用的 BM25F、Bm25fProximity、N-gram 和中文分词，不采用 Tantivy 默认字段加权 BM25。跨冻结段与 tail 的活动 N/df/字段长度由业务视图提供。
- 各通道先按全局候选窗口排名，再融合一次；默认窗口为 offset + length，显式候选上限可覆盖。ANN/候选截断不保证全库精确召回，relation_complete 只描述邻接遍历。
- 私有候选包稳定化、完整验证和同步后再发布。Searcher、worker、备份和构建持有保护；内部 commit、merge 或 GC 不能绕过业务权威删除在用文件。

## 收益、成本及非目标

减少自维护倒排格式与全文执行代码；仍需维护评分/分词适配、身份映射、原生 writer 生命周期和认证发布。即时写入包含原生 commit/reload，固定 Searcher 延长文件与内存存活；明确预算不等于全进程 RSS 硬上限。资源实测及限制见实施记录，不预设性能或内存收益。

Tantivy 不解决账本累计容量、完整 State 驻内存、服务总缓存预算和跨主机 HA。这些按[路线](roadmap.md)推进，不扩展本轮替换为性能或分布式专项。
