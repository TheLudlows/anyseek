## 真实 S3 验收前提

仅通过环境提供下列专用测试配置，不将值写入报告或仓库：

| 变量 | 用途 |
| --- | --- |
| `ANYSEEK_S3_TEST_ENDPOINT` | 专用 S3 兼容 HTTPS 服务端点 |
| `ANYSEEK_S3_TEST_BUCKET` | 已授权的隔离测试桶，不能使用生产桶 |
| `ANYSEEK_S3_TEST_REGION` | 服务签名所需 region |
| `ANYSEEK_S3_TEST_ACCESS_KEY_ID` | 已有测试身份的访问标识 |
| `ANYSEEK_S3_TEST_SECRET_ACCESS_KEY` | 同一测试身份的密钥，仅由环境注入 |

当前契约测试使用随机独立命名空间，要求对测试对象拥有 GetObject、PutObject、DeleteObject 权限以及条件创建语义；不要求桶管理、创建凭据或全桶列举权限。授权应限定到专用桶及测试前缀（包括 `anyseek-contract-tests/`、`partitions/` 和 `backups/`）。若桶使用额外加密策略，其所需权限须由现有管理员配置。测试只清理自身记录的对象，语义测试可能保留隔离命名空间供后续按已有保留策略处理。SQLite 权威目录与缓存目录也须隔离，不得复用生产目录。

默认不允许明文 HTTP；仅明确提供 `ANYSEEK_S3_TEST_ALLOW_HTTP=1` 时允许测试端点使用 HTTP。本轮未提供上述配置，未联系任何真实桶。进程退出/强杀验证仅覆盖进程中断与重启；不能证明操作系统断电时的页缓存、设备写缓存及文件系统持久顺序。
